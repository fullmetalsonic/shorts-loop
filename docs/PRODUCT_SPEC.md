## 0.2.9에서 유지하는 재생 계약 · 새 시작점 복구·긴 영상

0.2.6에서 도입한 일반 진행 정보 기반 넘김 요청의 **4.5초 전환 확인 시간 초과**만 제한적으로 자동 복구한다. 추가 스와이프 없이 같은 요청 앱·창에서 현재의 안전한 일반 영상을 관측한다. 시작 부근(`min(1초, 영상 길이의10%)` 이내) 표본과300ms~3초 이내의 정상 전진 재생을 확인하면 이전 누적값을 버리고 기존 정상 카운터로 설정 횟수를 다시 센다. 시작 확인 자체는 넘김 요청이 아니며, 0초 한 표본·정지0초·시간 경과만으로 복구하지 않는다.

긴 영상·광고·라이브·시간제·화면 분석 실패, 제스처 거부/취소, 권한 문제와 전환 중 앱·창 이탈 등 기존 안전정지는 유지한다. 복구 대기에서 긴 영상·광고·라이브·시간제·화면 분석으로 우회 이동하지 않는다. 전체OFF·목표0·설정 변경과 서비스 재연결의 기존 계약이 우선한다. 플로팅의 복구 대기·안전정지를 정상 회차와 구분한다. 상세 상태·예방 시험은 [PLAYBACK_RECOVERY](PLAYBACK_RECOVERY.md)를 따른다.

0.2.6에서 이전의 ‘모든 전환 확인 실패는 수동 재시작까지 정지’ 계약 중 위 일반 진행 시간 초과만 변경했다. 실패한 요청을 재전송하거나 감지되지 않은 재생을 완주로 가산하지 않는다. 최초 실패와 알림의 인과관계는 미확정이며,복구 구현을 원인 규명 완료라고 하지 않는다. 과거code28의 YouTube20회와 code26의 Instagram10회 PASS는 각각의 버전·앱에 한정된 기록이다. 같은 길이 쌍의 실기기 미관측 등 한계는 유지하며0.2.9의 새 검증·게시 결과와 혼합하지 않는다. [검증](VERIFICATION.md)과 [누적이력](CHANGELOG.md)에서 결과를 구분한다.

code22의 YouTube 실기기 관측2회는 긴 영상 기능 추가에 따라 중단된 이전 후보 기록이다. code26의 실제10개 시험이나 새 기능 검증에 합산하지 않는다.

- `skip_long` 기본OFF, `long_video_seconds` 기본60초·정수1~3600이다. 숫자 입력/완료·적용/−/+1초를 제공하며0·빈칸·음수·소수·범위 밖 초안은 저장하지 않는다. 읽을 때 손상된 값은60초로 안전 해석하되 정상 입력에서 잘못된 초안을60으로 몰래 확정하지 않는다.
- 일반 횟수 카드 바로 아래에 배치한다. 설치된 선택 대상 앱이 하나 이상이면 조작 가능하며 YouTube/Instagram 중 현재 전면의 선택 앱에만 적용한다. 미설치·미선택으로 비활성화해도 옵션·초안·확정값을 보존한다.
- 실행E=ON/긴 영상옵션ON이고 유효한 정상 진행 정보의 **총길이≥기준**일 때만 대상이다. 반복M>0은 조건이 아니므로M=0에서도 동작한다. E=OFF는 모두 중지하며 옵션 변경은M/N/E를 켜거나 바꾸지 않는다.
- 총길이 기준이지 대기 시간이 아니다. 같은 안전 페이지의 길이·창·실제 전진 재생을 안정 확인한 뒤 이동하며 재생 처음이나 완주를 기다리지 않는다.0초 정지·일시정지·버퍼링·조회 공백·비정상 탐색·화면 이탈에서는 길이만 보고 넘기지 않는다.
- 광고·라이브·사진·혼합·총길이 불명 영상은 긴 영상으로 추정하지 않는다. 진행 정보 없는 지원 Instagram은 기존 시간제 계약을 따르며M=0일 때 시간제는 여전히 중지한다. 짧은 정상 영상은 기존N회 경로를 유지한다.

## 1. 대상과 기능 범위

일반 YouTube 앱의 쇼츠 및 Instagram 앱의 지원되는 단일 동영상 릴스를 처음부터 설정 횟수만큼 관측한 뒤 다음 영상으로 이동한다. 0.2.1부터 인식된 Instagram 광고의 다음 페이지 이동을 선택 제공한다. 광고 제거/네트워크 차단·YouTube 광고 처리·타사 앱 개조·영상이나 계정 정보의 외부 전송은 범위 밖이다. 0.2.5는 공개 GitHub 업데이트 정보/APK 수신만 네트워크 예외로 추가한다.

0.2.0의 주요 변경은 다음과 같다.

- 기준 횟수 0~99, 숫자 직접 입력과 위/아래 화살표.
- 당시 0의 의미를 ‘자동 넘김 안 함’으로 명시. 최신 0.2.4에서는 광고 독립 동작 예외를 추가한다.
- 기준까지 순환 또는 0↔기준 전환의 두 플로팅 터치 방식.
- YouTube/Instagram 다중 선택 및 플로팅 표시 선택.
- 인앱 실행 토글 하나와 빠른 설정 연동.
- 플로팅 폭 축소와 투명도 증가, 작은 모서리 X 예외.
- 앱 아이콘과 일체감 있는 남색·청색·보라색 계열 및 직관적인 인앱 구성.

0.2.1 변경: Instagram 광고임을 확인하면 완주를 기다리지 않고 다음 페이지로 이동하며 별도 ON/OFF·기본 OFF를 제공했다. 당시 재생바 없는 일반 릴스는 수동 대기였다.

0.2.4 변경: 진행 정보를 읽지 못하는 안전한 단일 Instagram 영상에 선택형 시간제를 제공한다. 최초 후보 A의 15초/5~120초는 역사이며 후보 B와 공개판은 **10초/5~60초**다. 광고는 반복 횟수와 독립하여 0회에서도 사용할 수 있고 UI를 기능별 카드로 나눈다. 재생바 없음 자체를 광고로 간주하거나 사진·혼합·불명확 화면을 시간제로 넘기는 것은 여전히 범위 밖이다.

### YouTube 라이브 미리보기 · code21

- 기본 L=OFF, 대기 D=0초, 범위 0~60초다. 0은 인식·안전 확인 뒤 즉시 이동 요청이며 지연 1~60은 인식 후 기다리는 시간이다. 영상 길이나 완주 횟수가 아니다.
- E=ON/YouTube 선택/L=ON일 때 동작하며 M=0에서도 허용한다. E=OFF/L=OFF/YouTube 미선택이면 동작하지 않는다. 정상 영상 N회·Instagram 시간제·광고 설정은 변경하지 않는다.
- 정확한 전용 ID `immersive_live_preview_player`와 `reel_player_page_container` 아래 관계를 확인한다. 단일 활성 페이지가 `reel_recycler`와 거의 전체 경계 일치인 상태를 같은 노드·위치로 안정 확인해야 한다. 숨김·미리 로드·부분 표시·복수 페이지·수집 불완전·댓글/메뉴 등 차단 구조는 라이브 인식에서 거절한다. 텍스트·CTA·시청자 수를 라이브 판정 근거로 쓰지 않는다.
- 라이브 snapshot은 recognized이지만 일반 진행 usable과 화면 분석 대상은 아니다. 옵션 OFF에서도 라이브 페이지로 인식하여 일반 영상에서의 전환을 확인한 뒤 대기할 수 있다.
- 페이지 identity는 RAM의 접근성 노드 동일성을 사용하고 제목/숫자/CTA 변경으로 바꾸지 않는다. 같은 노드를 다른 방송에 재사용하면 구분하지 못할 수 있다. 다음 identity 확인이 불충분하면 중복 요청하지 않고 안전 정지한다.
- 실제 방송 참여 버튼은 누르지 않는다. 새 권한·OCR·화면 캡처·오디오 분석·인터넷 요청을 추가하지 않는다. 라이브 인식 코드와 일반 영상 진행 판독은 분리하며 모든 앱 버전 지원을 보장하지 않는다.
- 상세 안전 조건·검증 상태는 [LIVE_SKIP](LIVE_SKIP.md), 최종 검증·게시 결과는 [VERIFICATION](VERIFICATION.md)를 따른다. code21은 공개 시험판이며 일반10연속 PASS와 code20의 개별 라이브 실제 시험을 구분한다. 과거 일반 영상 시험으로 라이브 실제 이동을 PASS 처리하지 않는다.

## 2. 상태와 용어

| 값 | 의미·범위 |
|---|---|
| 기준 N | 인앱에서 확정한 총 재생 횟수, 0~99 |
| 현재 M | 실제 영상에 적용하는 횟수, 0~N |
| 현재 회차 C | 완주를 추적 중인 회차, 0~M |
| 실행 E | 실행 제어 ON/OFF. M=0과 구분 |
| 플로팅 F | 표시 사용 설정. 실행 여부와 독립 |
| 터치 방식 | ROTARY=0: 0…N 순환 / TOGGLE=1: 0↔N |
| 적용 앱 | YouTube·Instagram 각각 선택, 기본 YouTube만 |
| 라이브 옵션 L | `skip_live` ON/OFF, 기본 OFF. YouTube 쇼츠 라이브 미리보기만 |
| 라이브 대기 D | `live_delay_seconds`, 기본 0초·정수 0~60초. 0은 인식 후 바로 넘기기 |
| 광고 옵션 A | `skip_ads` ON/OFF, 기본 OFF. Instagram에만 적용 |
| 긴 영상 옵션 G | `skip_long` ON/OFF, 기본OFF. 현재 선택 앱의 일반 영상·M=0에서도 가능 |
| 긴 영상 기준 H | `long_video_seconds`, 기본60초·정수1~3600초. 확인된 총길이≥H |
| 시간제 T | `timed_fallback` ON/OFF, 기본 OFF. 진행 정보 없는 지원 Instagram 영상만 |
| 대기 시간 S | `fallback_seconds`, 기본 10초·정수 5~60초. 횟수와 별도 저장 |
| 화면 분석 V | `visual_assist` ON/OFF, 기본 OFF·별도 동의·Android 14 이상 시험 기능 |
| 업데이트 자동 조회 U | 재생 설정과 별도 저장, 기본 ON. 앱을 열 때 마지막 시도 후 24시간 간격으로 조회 |

정상 추적의 플로팅은 C/M을 표시한다. N=5, M=2이면 `1/2`·`2/2`이며 기준 5는 보존한다. 시간제 중에는 `10초 → 9초` 등 남은 시간, 이동 확인 중에는 해당 상태를 표시한다. M=0에서 해당 앱 선택/A=ON이면 ‘광고’, L=ON이면 ‘라이브’, 둘 다이면 ‘광·라’를 표시하여 일반 영상 정지와 별도 기능을 구분한다. 라이브 대기 중에는 남은 초, 이동 확인 중에는 ‘다음’을 표시한다. 화면 분석의 `…/N`·`~n/N`은 학습/추정이며 확정 완주가 아니다.

0은 실행 전체 종료가 아니라 **일반 영상 반복·시간제·화면 분석 중지** 값이다. E=ON/M=0에서도 선택 앱/G=ON이면 기준 이상 긴 영상,Instagram 선택/A=ON이면 광고,YouTube 선택/L=ON이면 라이브를 넘길 수 있다. 하단은 반복 중지와 활성 독립 옵션을 구분한다. E=OFF는 모두 중지하고 플로팅도 닫는다. **광고 전용 사용=M=0 + Instagram선택 + A=ON + G=OFF + L=OFF + E=ON**이다.

`live_delay_seconds`의 저장값이 0~60 범위 밖이거나 잘못된 타입이면 0초로 읽는다. 라이브 옵션 기본 OFF이며 기존 설정은 초기화하지 않는다.

| 설치 허용 화면 복귀/설치 취소 | E=OFF 유지. 복귀만으로 설치 또는 실행을 자동 재개하지 않음 |

N=0이면 M도0이며 실행 ON이나 플로팅 탭이 과거 양수 설정을 복원하지 않는다. 플로팅 표시 OFF는 카운트를 초기화하는 설정이 아니지만, 설정 앱으로 전환하는 행위 자체는 대상 영상 앱을 벗어나므로 앱 전환 보호가 적용된다.

잘못된 저장값은 순수 정책으로 정규화한다. 정상 입력 UI에서는 잘못된 숫자를 임의 기본값으로 확정하지 않고 오류를 보여 준다. 기준 N과 현재 M 등 함께 변경되는 값은 SharedPreferences의 한 Editor로 갱신한다.

### GitHub 업데이트 계약 · 0.2.5

- 기존 Public 저장소 `fullmetalsonic/shorts-loop`의 공개 릴리스 정보와 업데이트 manifest만 조회한다. draft를 제외하고 공개된 prerelease도 후보에 포함하며 설치본보다 큰 versionCode와 현재 OS 호환성이 필요하다. 임의 URL 입력·다른 저장소·검증 우회 경로를 제품에 제공하지 않는다.
- U는 기본 ON이다. 앱 열기/복귀 시 최초 조회 또는 마지막 시도 후 24시간이 지난 경우만 자동 조회한다. 실패도 시도 시각에 포함한다. 기기 시각이 뒤로 바뀐 경우의 복구 예외를 둔다. 수동 확인은 별도이며 5초 연속 누름 방지를 적용한다. 백그라운드 감시·알림 권한·자동 다운로드는 없다.
- 더 높고 적용 가능한 후보를 알고 있을 때만 상단 새 버전 배너를 표시한다. 저장한 후보도 설치본/OS와 다시 비교하며 배너 탭은 업데이트 카드 이동만 한다. U=OFF는 이미 확인한 후보를 지우는 동작이 아니다.
- 조회·다운로드·설치는 별도의 단계다. 사용자 다운로드 요청 후 진행률/취소를 제공한다. HTTPS의 정해진 GitHub/릴리스 자산 출처·파일 크기·SHA256을 확인하고 APK의 패키지·버전·최소 OS·설치본 서명을 검사한다. 검사 실패·통신 실패·취소는 설치로 이어지지 않는다. 최종 APK 서명 검증과 설치 허용은 Android 설치기가 담당한다.
- 내려받은 APK는 앱 내부 전용 저장소를 사용한다. 설치 직전 다시 검증하며 설치기에는 제한된 읽기 URI 권한으로 전달한다. 공유 저장소 전체 권한은 요청하지 않는다.
- 사용자가 ‘업데이트 설치’를 누르면 먼저 E=OFF로 바꾸며 N/M/앱/광고/시간제/위치는 보존한다. `REQUEST_INSTALL_PACKAGES` 선언만으로 설치 권한을 받은 것으로 취급하지 않는다. 필요하면 사용자 확인 후 자기 앱의 ‘이 출처 허용’ 설정으로 이동하며 사용자가 직접 허용한다.
- 설치 허용 화면에서 돌아오면 설치 버튼을 다시 눌러야 한다. 시스템 설치 화면에서도 사용자가 최종 확인하며 설정 화면 복귀·설치 창 호출만으로 설치 완료를 표시하지 않는다. 취소 후에도 E=OFF를 유지하고 자동 재시작하지 않는다.
- 0.2.4에는 이 업데이트 기능이 없다. 0.2.5 최초 전환은 같은 서명 APK의 수동 덮어쓰기 설치가 필요하다. 이후 호환되는 공개 업데이트부터 인앱 경로를 사용한다. 다른 서명의 개인/CI 빌드로 교체 가능하다고 보장하지 않으며 삭제를 자동 복구 수단으로 사용하지 않는다.

## 4. 감지와 자동 넘김

- 선택된 앱 패키지와 포커스를 확인한 다음 해당 앱 전용 감지기를 호출한다. 두 앱이 선택되어도 현재 앞에 있는 앱만 대상이다.
- YouTube는 쇼츠 컨테이너와 단일 진행막대의 최신 시간을 확인한다.
- Instagram은 릴스 pager 내부의 단일 영상 컨테이너, 단일 media, `scrubber` 진행막대와 유효한 밀리초 범위를 확인한다.
- 확인된 Instagram 사진 carousel은0.2.9의별도사진계약을따른다. 그밖의미지원사진/혼합,댓글/메뉴,식별정보부족은대기한다. 정상영상은긴영상조건→기존횟수,진행정보없는지원단일영상은기존시간제/화면분석을따른다. 확인된광고는광고계약을우선하며사진옵션으로광고OFF를우회하지않는다. 모든광고·메뉴·사진형태의판별을보장하지않는다.
- 앱 패키지를 포함한 식별값으로 영상과 앱을 구분한다. 앱 전환 때 진행 상태를 초기화하여 다른 앱의 카운트를 이어 쓰지 않는다.
- 정상 진행 정보는 약 300ms 간격으로 관측하고 영상 끝→처음 이동·관측 진행량·최소 경과시간을 확인한다. 이 N회 경로를 단순 시간 타이머로 대체하지 않는다.
- 중간에 켜면 현재 부분 재생은 완주로 세지 않는다. 다음 시작까지 C=0, 추적 중 C=1…M이다.
- 정상 횟수 경로의 자동 제스처는 영상 영역 높이 75%에서25%까지 아래→위로 이동한다. 플로팅 영역과 시스템 모서리를 피한다. Instagram 시간제와 광고는 정확히 식별한 pager 동작을 사용한다.
- 스와이프 요청 성공과 다음 영상 전환 성공을 구분한다. 전환이 확인되지 않으면 연속 재시도하지 않는다. 0.2.6의 일반 진행 기반4.5초 시간 초과만 새 시작점 관측 복구에 들어가며, 그 밖의 실패는 재시작 안내 상태로 멈춘다. 복구 중 새 시작 확인과 새 완주 관측을 생략하지 않는다.

### Instagram 광고 즉시 넘김 계약

- E=ON, Instagram 선택, A=ON을 모두 만족하고 전면의 Instagram 릴스에서 광고 근거와 안전한 화면 구조를 확인해야 한다. **M>0은 광고 조건이 아니며 M=0에서도 광고만 넘길 수 있다.**
- 기본 A=OFF이다. E=OFF 또는 A=OFF는 광고를 중지한다. A 변경은 N/M/E를 바꾸지 않는다. 업데이트 전 A=ON이었다면 새 0회 동작에 영향을 주므로 설명서에서 확인을 안내한다.
- 광고 라벨·컨테이너 구조를 검사한다. 캡션·작성자·본문에 ‘광고’라는 단어가 있거나 재생바가 없다는 이유만으로 광고로 간주하지 않는다.
- 실측된 우하단 동영상 광고 배지는 `clips_ufi_component` 내부의 작은 라벨이고 클릭 가능한 부모 영역이 라벨보다 클 수 있다. 해당 구조·위치·라벨의 정확한 일치를 함께 검사한다. 일반 캡션의 `#광고`만으로 이 구조를 대체하지 않는다.
- 광고를 발견해도 전체 화면의 댓글/메뉴/복수 pager/지원하지 않는 구조 검사를 생략하지 않는다.
- 새로 조회한 정확한 릴스 pager에 `ACTION_SCROLL_FORWARD`를1회 요청한다. 광고 링크·CTA·구매 버튼에 클릭 동작을 보내지 않으며 거절 시 좌표 스와이프로 대체하지 않는다.
- 릴스 영상 위의 ‘더 알아보기’ CTA 카드가 있는 광고는 페이지 전체 넘김 대상이다. 별도 창 팝업의 X를 찾아 닫는 기능은 미구현이며 범위 미확정이다.
- 광고는 진행시간 없이 구조로 인식한 페이지이다. 시간값이 없지만 확실한 단일 영상·식별정보가 있는 일반 영상은 전환 확인에 사용할 수 있다. 다음 이동 여부는 별도의 T/M/안전 조건으로 판단하며 ‘직전 광고에서 넘어왔다’는 사실만으로 다시 넘기지 않는다.
- 요청 중에는 추가 요청을 금지한다. API가true를 반환했다고 성공으로 확정하지 않는다. 최소1.2초 이후 다른 페이지를 확인하며4.5초까지 확인되지 않으면 안전 정지한다.
- 광고끼리 고정 식별값을 공유하므로 늦은 페이지 이동 이벤트만으로 연속 광고를 성공 처리하지 않는다. 다른 광고임을 구분할 수 없으면 실제로 이동했어도 안전 정지할 수 있다. 같은 광고·무정보·null 상태에서 무한 재시도하지 않는다.
- 이동 확인 pending 도중 화면 구성 변경·드래그 등 세션 중단은 단순 gate 취소로 새 요청을 허용하지 않는다. `interruptSession`을 통해 확인 중이면 안전 정지하고, 확인 중이 아니면 정상 초기화한다. 독립 검토에서 지적한 중복 광고 요청 위험에 대한 보완이다.

### Instagram 진행 정보 없는 영상의 시간제 계약

- E=ON/M>0/Instagram 선택/T=ON이고, 전면의 안전한 단일 동영상·식별정보·진행 정보 없음·일시정지 아님을 확인해야 시작한다. 기본 T=OFF/S=10초, 정수 5~60초이며 ±1초로 조절한다.
- 정상 진행 정보가 있으면 N회 경로가 우선이다. 중간부터 켜서 다음 처음 재생을 기다리는 C=0/M>0을 정보 없음으로 취급하지 않는다. YouTube는 시간제 대상이 아니다.
- S는 총 대기 시간이다. M=2/S=10이면 정상 영상은 총 2회, 정보 없는 대상은 총 10초이며 20초로 곱하지 않는다. 초 값 저장은 M과 독립이지만 **M=0에서는 시간제 중지**다.
- 첫 안전 관측부터 시간을 세며 같은 화면 확인 구간도 S에 포함한다. 새 영상·설정 변경·창 크기 변경·시간 역행·긴 조회 공백은 초기화한다. 1.5초 초과 조회 공백을 누적해 복귀 즉시 넘기지 않는다.
- 감지된 일시정지·댓글·메뉴·잠금·앱/창 전환·플로팅 조작·E=OFF/M=0/Instagram 해제는 타이머를 취소한다. 안전한 시청 상태 복귀 후 처음부터 센다. 모든 앱 UI·정지를 감지한다고 보장하지 않는다.
- 사진·혼합·식별 불가 화면과 광고는 타이머로 우회하지 않는다. 시간이 되면 해당 릴스 pager에 `ACTION_SCROLL_FORWARD` 한 번을 요청하고 다른 영상 식별정보를 확인해야 성공이다. 같은 영상에 시간 정보만 생긴 것은 이동 성공이 아니다. 실패는 안전 정지하고 무한 재시도하지 않는다.
- 영상 길이·완주·정확 N회를 알아내는 기능이 아니다. 긴 영상은 완주 전, 짧은 영상은 여러 재생 후 이동할 수 있다. 새 캡처·마이크·오디오 권한 없이 기존 접근성 정보로 동작한다.

### 화면 분석 및 미연결 실험의 경계

기존 화면 분석 보조 V는 기본 OFF·Android 14 이상·Instagram 선택·별도 사용자 확인 후 RAM에서만 화면 반복을 비교하는 시험 기능이다. 학습에 추가 재생이 필요하며 `~n/N`은 추정이다. 정확한 총 N회를 보장하지 않는다. T와 V가 모두 ON이면 시간제가 우선하며 새 화면 분석을 하지 않고 V 선택값은 보존한다.

미연결 `VisualSequenceTracker` 전체 구간 비교 실험은 위의 선택형 보조와 다르다. 실험 20개 중 18 PASS/2 FAIL(주기 오추정·학습 실패)을 보존하고 배포 앱/제품 시험의 sourceSets에서 제외한다. 제품 시험 PASS를 미연결 실험까지 포함한 전체 PASS로 표현하지 않는다. 별도 [오디오 수신](AUDIO_PROBE_TRIAL.md)·[음향 패턴](AUDIO_PATTERN_TRIAL.md) 진단 앱은 제품 자동 넘김에 연결하지 않으며 이번 제품 APK 첨부 대상이 아니다.

## 5. 안전·정확도 제한

- 선택 앱의 지원 화면, 각 경로의 진행 정보/시간제 구조/입증된 광고 조건, 화면 켜짐/잠금 해제, 입력초점 조건을 만족할 때만 자동 동작한다.
- 댓글·키보드·메뉴·앱 전환·드래그·영상 변경·긴 관측 공백·수동 탐색으로 판단한 점프는 보수적으로 추적을 초기화한다.
- 정상 진행 영상의 일시정지·버퍼링 동안 시간 경과만으로 넘기지 않는다. 시간제는 감지된 중단에 한해 취소하므로 완주를 보장하지 않는다. 광고는 완주 및 M과 독립이지만 E=OFF에서는 멈춘다.
- 현재값 변경·X·OFF는 이전 추적/예약 동작보다 우선한다. 플로팅 표시 변경은 별도 표시 경로이다.
- 프로세스나 접근성 서비스가 다시 연결되면 자동 실행하지 않고 E=OFF로 시작한다.
- code17부터 접근성 미연결 시 ‘접근성 연결 확인 · 해결 방법 보기’ 배너와 ‘접근성 설정·다시 연결’ 버튼을 표시한다. 이미 ON인데 동작하지 않으면 Android에서 해당 서비스를 OFF→ON하고 연결 후 전체 실행을 다시 ON하도록 안내한다. 화면 분석 OFF에서도 기본 감지·다음 이동에 접근성이 필요함을 명시한다. 안내 표시·설정 화면 이동은 권한 자동 변경이나 E 자동 시작을 하지 않는다.
- 빠른 설정창·다른 포커스 창·PiP에서는 대기한다. 다른 앱의 비포커스 플로팅이나 팝업 가림을 전부 판별한다고 보장하지 않는다.
- 0.1.4의 최신 접근성 시간 갱신·양자화된 표시 허용, 0.1.5의 입력초점 기반 보호를 유지한다. 작은 수동 탐색과 정상 표시 지연의 완전한 구분은 보장하지 않는다.
- 진행 정보가 없는 일반 영상은 지원 조건과 선택 옵션에 따라 시간제/추정/수동 대기로 나뉜다. 3초 미만·지원하지 않는 시간 표현·특수 콘텐츠·앱 UI 변경은 완주 감지 실패/대기가 가능하다. 재생 정보 없음 자체로 광고 판정을 하지 않는다.
- 회전·접기·펼치기 후 저장 위치를 현재 화면 안으로 보정하는 정책과 실제 실기기 전환 성공은 별도 검증 항목이다.

## 7. 저장·이전 계약

주요 키는 `ceiling`, `target`, `tap_mode`, `floating_enabled`, `youtube_enabled`, `instagram_enabled`, `skip_ads`, `skip_live`, `live_delay_seconds`, `skip_long`, `long_video_seconds`, `timed_fallback`, `fallback_seconds`, `visual_assist`, `enabled`, `last_nonzero`, `x`, `y`, `settings_version`이다. 설정 스키마는1을 유지하고 새 선택 옵션은 안전한 getter 기본값을 사용한다.

- 기존 양수 target은 N/M에 함께 이전한다.
- 기존 target=0은 M=0을 보존하고 마지막 양수 값을 N으로 이전한다. 유효한 값이 없으면 N=2이다.
- 기본 YouTube 선택/Instagram 미선택/F=ON/ROTARY이다. 위치와 무관한 기존 값은 보존한다.
- `skip_long`/`skip_ads`/`skip_live`/`timed_fallback`/`visual_assist`가 없거나 올바른 boolean이 아니면false로 읽는다. 기존 값은 이전 과정에서 지우거나 기본값으로 덮어쓰지 않는다. 광고0회 독립 변경 후 기존A=ON의 효과를 사용자에게 안내한다.
- `fallback_seconds`가 없거나 타입/범위가 손상됐으면 정책 기본값 10초로 읽는다. 정상 UI는 오류 입력을 10으로 몰래 확정하지 않고 오류를 표시한다. 15초/5~120초는 과거 후보 A이며 최신 범위 밖 값은 그대로 실행하지 않는다.
- 이전은 같은 설정에 반복 적용하지 않는다. 새 버전 설정을 구버전 기준으로 덮어쓰지 않는다.
- 현재값 target 변경은 N을 바꾸지 않는다. 기준 변경은 N/M을 함께 변경한다.
- 저장소 단위시험의 메모리 기반 SharedPreferences 검증은 Android 실제 디스크 저장·업데이트 설치·재시작 검증을 대체하지 않는다.
- 업데이트 전용 `updates` 저장소는 자동 조회 선택·마지막 시도 시각·후보 메타데이터를 보관한다. 다운로드/조회 상태를 기존 재생 설정 스키마에 섞지 않는다. 설치 진입의 E=OFF 외에는 재생 설정을 수정하지 않는다.

## 8. 0.1.5에서 변경된 기준

0.1.5의 0/1/2 전용·고정 순환·항상 플로팅 표시·타일 ON 시 마지막 양수 복원 규칙은 위의 N/M·두 모드·선택 표시·기준값 복원 규칙으로 변경한다. 기존72% 전체창 불투명도와 숫자/X 각각48dp 규격은 더 작은 반투명 플로팅으로 변경했다. X 크기는 폭 축소와 터치 편의 사이의 절충이다.

과거 YouTube에서 검증한 완주·상향 스와이프·포커스 보호 결과는 유지할 회귀 근거이지, 신규 Instagram/입력 UI/0회 타일 의미까지 검증 완료됐다는 뜻은 아니다. 버전별 실제 결과는 누적 검증 기록을 따른다.

0.2.0의 ‘광고에서는 항상 대기’는 0.2.1의 별도 광고 옵션으로 변경했다. 0.2.4는 **0회에서도 광고만 사용 가능**으로 추가 변경했으며 옵션 기본 OFF와 기존 저장값 보존은 유지한다. 기존 A=ON이면 새 버전의 M=0 동작도 달라지므로 ‘업데이트 후 동작 불변’으로 설명하지 않는다. 정보 없는 지원 Instagram 영상은 새 선택형 시간제 또는 보존된 화면 분석 시험 경로를 사용할 수 있고 그 외는 수동 대기다.
