# UI·인간공학 기준 · ShortsLoop 0.2.2

0.2.2 추가: 사용 준비 카드에 별도 BatterySetupPanel을 배치한다. 현재 Android 절전 예외 상태를 문구+색상으로 표시하고, 설정 버튼은 적용 후에도 '확인하기'로 유지한다. 수동 경로·취소·배터리 비용·지원 한계를 안내한 뒤 자기 앱 설정으로만 이동한다. onResume 상태 갱신은 실행 토글을 조작하지 않는다. 버튼 최소48dp; 정적 사용성 리뷰만 완료했고 새 메뉴의 실기기 잘림·터치·복귀 검사는 보류다.

## 목적과 상태

사용자 요청은 ‘아이콘과 일체감 있으면서 인간공학적으로 직관적인 인앱 구성’이다. 자주 쓰는 설정과 종료 조작을 쉽게 찾고, 플로팅을 사용하지 않는 사람에게 불필요한 설정·권한을 요구하지 않는 것을 우선한다.

아래는 현재 네이티브 구현의 기준이다.0.2.0 기본 입력·플로팅 조작과0.2.1 시험 빌드v021b의 일부 광고 동작은 실기기 확인했지만, 모든 화면 크기·큰 글꼴·후속 보완 빌드의 전체 UX 검증을 완료했다는 선언이 아니다. 실제 결과는 [검증 기록](VERIFICATION.md)을 참조한다. 동작 계약은 [PRODUCT_SPEC](PRODUCT_SPEC.md), 단계별 조작은 [USER_GUIDE](USER_GUIDE.md), 광고 추가 범위는 [승인 설계](ADS_PLAN_2026-08-27.md)에 연결한다.

## 1. 화면 구조와 사용 순서

```text
앱 아이콘  쇼츠 자동 넘김
           보고 싶은 횟수만큼, 다음 영상으로

1 반복 횟수
  한 영상을 총 몇 번 볼까요?
  [ 큰 숫자 입력 ] [ ▲ ]
                  [ ▼ ]
  0의 의미·입력 안내 / 필요할 때만 적용 버튼
  현재 적용 횟수 또는 기준/현재 값 차이

2 사용할 앱
  [체크] YouTube 쇼츠
  [체크] Instagram 릴스
  광고 바로 넘기기 [토글]  ← 기본 OFF, Instagram 선택 시 조작
  Instagram 한정·실행 켜짐/1회 이상·일반 릴스 감지 한계

플로팅 리모컨
  화면 위에 숫자 표시 [토글]
  표시 ON일 때만 두 터치 방식과 이동/종료 설명

사용 준비
  현재 연결 상태
  부족한 권한 버튼만 표시
  백그라운드 실행 · 배터리
    절전 예외 상태 / 수동 설정 안내 버튼
  빠른 설정에 실행 토글 추가

사용법과 감지 한계 보기 [펼치기]
버전
──────────────────────────
자동 넘김 실행     [켜짐/꺼짐]  ← 하단 고정
현재 상태 / 다음 행동 설명
```

설정을 위에서 아래로 정하고 마지막으로 실행한다. 종료는 화면 아래 고정 위치에서 찾는다. 플로팅 관련 기능은 한 카드에 모으고 표시를 끄면 세부 방식을 접어 시각적 부담을 줄인다. 권한이 이미 연결된 사용자는 매번 설정 버튼을 다시 볼 필요가 없다.

사용자가 하단 실행 영역의 목적을 질문했다. 고정 이유는 설정 화면 어디서든 현재 상태를 보고 끌 수 있게 하는 것이다. 현재 높이가 크다는 개선 여지가 있어 높이 축소와 ‘전체 자동 넘김’ 명칭을 제안했지만, 변경 승인은 없으므로 현재 높이·명칭을 유지한다. 제안을 구현 완료로 기록하지 않는다.

광고 옵션은 적용 앱 바로 아래에 붙여 Instagram에 종속된 기능임을 설명한다. Instagram을 해제하면 옵션 조작을 비활성화하지만 값은 지우지 않는다. 광고를 없애는 기능이 아니라 광고 페이지를 넘기는 기능이며,0회는 광고까지 멈춘다는 점을 도움말에 명시한다. 재생바 없는 일반 릴스를 광고로 오해하지 않도록 수동 넘김 안내를 분리한다.

옵션 아래에 ‘끄면 광고는 직접 넘겨 주세요’를 명시해 OFF의 결과를 바로 알게 한다. 릴스 내부의 ‘더 알아보기’ 카드가 팝업처럼 보여도 카드 클릭이나 닫기를 하는 기능은 아니다. 해당 광고 페이지 전체를 넘긴다. 별도 창 광고 팝업 자동 닫기는 미구현/범위 미확정으로 구분한다.

## 2. 아이콘과 화면의 일체감

아이콘의 짙은 남색·청색/보라색 빛을 화면 색상에 연결한다. 아이콘에는 입체감과 발광감을 남기고, 설정 화면은 글자와 컨트롤의 가독성을 위해 평평하고 절제된 카드로 구성한다. 모든 버튼에 광택·그림자·애니메이션을 넣는 방식은 사용하지 않는다.

| 토큰 | 현재 값 | 역할 |
|---|---|---|
| 배경 | `#080F1B` | 전체 남색 바탕 |
| 카드 | `#111D2E` | 설정 묶음 구분 |
| 테두리 | `#2A3D53` | 카드·조작 경계 |
| 본문 | `#F1F7FF` | 주요 제목·숫자 |
| 보조 글자 | `#AEC1D7` | 설명·다음 행동 |
| 청색 강조 | `#74DCFF` | 선택/실행/현재값 |
| 보라색 | `#BEA4FA` | 아이콘 계열의 보조 팔레트; 모든 컨트롤에 강제 적용하지 않음 |
| 주의 | `#FFCE81` | 차단·오류 상태 |

색상만으로 켜짐/꺼짐을 구별하지 않는다. 체크/라디오/스위치의 모양과 텍스트 상태를 함께 사용한다. 0회는 청색 스위치가 켜져 있어도 ‘자동 넘김 안 함’ 문구를 보여 혼동을 줄인다.

## 3. 입력과 터치 영역

- 큰 숫자는40sp, 입력창104dp 높이로 한 번에 찾도록 한다. 화살표는 각각52dp 높이이며 ‘한 회 늘리기/줄이기’ 접근성 설명을 갖는다.
- 타이핑은 임시값으로 유지한다. 완료/적용 전에는 기존 값을 지우는 순간을0으로 저장하지 않는다. 숫자 오류에는 입력창에서 구체적인 범위를 안내한다.
- 입력이 바뀐 동안에만 적용 버튼을 보여 ‘입력한 값이 아직 확정되지 않았다’는 단서를 준다. 키보드의 완료로도 같은 동작을 할 수 있다.
- 화살표는 유효한 입력에서 한 단계씩 즉시 적용한다. 범위 끝에서는 더 진행하는 버튼을 비활성화한다.
- 앱 체크 항목은 최소56dp 높이, 라디오 항목은 최소64dp, 기본 버튼은 최소48dp이다. 작은 체크 그림만 정확히 겨냥하지 않아도 행을 눌러 조작할 수 있다.
- 라디오 행은 전체 가로폭을 터치 대상으로 한다.0.2.0에서 짧은 문구 오른쪽 빈 영역이 반응하지 않는 문제를 수정하고 재시험했다.
- 인앱 실행 스위치는56dp 높이 영역에 놓고 상태 설명 옆에 고정한다. 긴 설명은 스크롤하고 실행 제어는 같은 위치에 남는다.
- 앱 전환·권한 부족·0회·실행 OFF를 서로 다른 문구로 설명한다. ‘ON’ 하나로 실제 자동 스와이프가 진행 중이라고 오해하지 않게 한다.
- 완료/Enter 후 비조작 컨테이너 전체가 회색 강조되는 문제는 기본 포커스 강조를 해제해 수정·재시험했다. 편집 포커스와 실제 선택 상태가 혼동되지 않게 한다.
- 광고 옵션의 체크 상태를 복원하거나 주기적으로 갱신할 때에는 rendering guard를 적용해 실행·횟수 설정이 뜻하지 않게 변경되지 않게 한다.

## 4. 플로팅 크기 절충

기존124×56dp에서72×56dp로 약42% 폭을 줄였다. 숫자 영역48×56dp를 유지하면서 오른쪽 위 X는24×24dp로 축소했다. X 아래 빈 부분까지 숨은 외곽 클릭 영역으로 확장하지 않는다.

일반적인48dp 터치 목표를 X에는 충족하지 못한다. 이는 사용자에게 폭 축소와 터치 영역의 충돌을 설명하고 승인받은 예외이며, ‘접근성 목표 완전 충족’으로 보고하지 않는다. 종료를 작은 X에만 의존하지 않도록 인앱 실행 토글과 빠른 설정을 함께 제공한다.

배경 알파128/255와 창 알파0.8의 곱으로 배경은 약40% 불투명도를 의도한다. 숫자·X는 창 알파에 따른 약80%로 더 선명하게 유지한다. 실제 영상 밝기와 움직임에 따른 읽기 쉬움은 별도 확인한다. 99/99는 자동 글자 크기 조절을 사용하므로 작은 글자로 줄어드는 조건을 특히 검사한다.

## 5. 사용한 디자인·구현 방법

- Figma 편집·보드·프로토타입은 사용하지 않았다. Figma로 제작했다거나 전문 도구의 자동 감사를 통과한 것처럼 표시하지 않는다.
- 아이콘은 사용자 참고 사진과 승인된 스타일을 바탕으로 이미지 생성 도구를 사용한다. 생성 시안과 실제 런처 자산 적용·마스크/소형 가독성 검증은 구분한다.
- 화면은 Java/native Android로 직접 구현한다. `UiTheme`는 색상·카드·여백, `SettingsScreen`은 배치, `CountEditor`는 입력, `MainActivity`는 설정/상태 연결을 담당한다.
- 별도 웹 목업의 모양만으로 품질을 판단하지 않고, 빌드한 APK의 실제 화면과 터치·키보드 동작으로 확인한다. 전문성은 도구 사용 명칭이 아니라 근거 있는 배치·상태 설명·실제 검증으로 평가한다.

순수 정책·저장소 자동시험은 터치 위치나 글자 잘림을 확인하지 않는다. 데스크톱1920×1080 브라우저 UI는 이 네이티브 앱의 적용 대상이 아니며, 대신 폴드 커버/펼친 화면과 관련 좁은 화면·큰 글꼴을 우선한다. 실제 수행 여부와 결과는 이 표를 PASS로 일괄 변경하지 않고 검증 문서에 증거와 함께 기록한다.

v021b 단계 자동시험145개 PASS와 위 실기기 증거를 구분한다. 이후 독립 검토에서 이동 확인 중 드래그·화면 구성 변경으로 gate가 취소되어 중복 요청될 수 있는 위험을 찾아 안전 정지 경로로 보완했다. 최종v021c 빌드·직접JUnit148·정적연결·독립 재리뷰 PASS, 설치·재추출 해시 일치. YouTube N1과 타일 OFF/ON 실제 회귀 PASS. 새 광고 안내 문구는 실제 화면에서 읽을 수 있음을 확인했고 별도 PiP가 겹치는 것은 외부 창으로 구분했다. 실제 pending 순간 회전/드래그는 미실행이다.

광고는1회 이동 요청 후 최소1.2초 이후 전환 확인,4.5초 미확인 시 안전 정지하는 구조이다. 같은 식별값의 연속 광고나 확인 도중 조작/화면 변경에서는 안전 정지가 가능하므로 ‘모든 광고 자동 처리’라는 UI 약속을 하지 않는다. 폴드 펼침·큰 시스템 글꼴은 여전히 미실행이다.
